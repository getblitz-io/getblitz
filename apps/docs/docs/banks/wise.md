# Wise Bank Integration Guide

This guide walks you through connecting a [Wise](https://wise.com) account to GetBlitz to receive SEPA Instant payments directly into a Wise balance.

## Prerequisites

Before you begin, you'll need:

- A **Wise Business** (or Personal) account that can hold the currencies you want to receive.
- The ability to generate a [Personal API token](https://docs.wise.com/guides/developer/auth-and-security/personal-api-token) inside that account.
- _(Optional, recommended for testing)_ A [Wise Sandbox](https://sandbox.transferwise.tech) account.

## Authentication Model

Wise offers two API access models. GetBlitz uses the simpler one:

| Model                                               | Who it's for                                                         | Used by GetBlitz? |
| --------------------------------------------------- | -------------------------------------------------------------------- | ----------------- |
| **OAuth 2.0** (client credentials, mTLS, JOSE, SCA) | Large enterprise partners with a Wise Platform partnership agreement | ❌ No             |
| **Personal API token**                              | SMBs automating their own Wise.com business account                  | ✅ Yes            |

Personal API tokens are simple bearer tokens generated by the account owner — no redirect flow, no client secret, no mTLS handshake. The token does not expire and is scoped to the account that created it. This makes Wise a "single-tenant" integration: you connect _your own_ Wise account, you can't connect a customer's Wise account on their behalf.

> If your use case requires acting on behalf of third-party Wise users (multi-tenant marketplace, white-label), you'll need an OAuth 2.0 partnership with Wise instead. That flow is **not** currently implemented in GetBlitz — see the [Wise Platform docs](https://docs.wise.com/guides/developer/auth-and-security) for what that involves.

## Step 1: Generate a Personal API Token

### Sandbox

1. Sign in to the [Wise Sandbox](https://sandbox.transferwise.tech).
2. Go to **Settings** → **API tokens**.
3. Click **Add new token**, give it a name like "GetBlitz Sandbox", select **Full access**, and confirm.
4. **Copy the token immediately** — Wise will only display it once.

### Production

1. Sign in to your live Wise account at [wise.com](https://wise.com).
2. Go to **Settings** → **API tokens**.
3. Click **Add new token**, give it a name like "GetBlitz Production", select **Full access**, and confirm.
4. **Copy the token immediately**.

> **Security**: Treat the API token like a password. Anyone with it can list your balances, create transfers (depending on scope), and register webhooks against your account. Store it only in GetBlitz's encrypted credentials store.

## Step 2: Start Configuration in GetBlitz

In your GetBlitz dashboard:

1. Navigate to **Banks** → **Connect**.
2. Select **Wise** as the provider.
3. You'll see a configuration form with these fields:
   - **API Token** — paste the token from Step 1.
   - **Sandbox Mode** — toggle on if you generated a sandbox token.

> Unlike Qonto and Revolut, **there is no callback URL to register and no OAuth redirect**. The token is the credential.

## Step 3: Select a Wise Profile

After you enter the API token and sandbox toggle, the **Wise Profile Selector** step appears below the configuration fields.

A Wise account can have multiple profiles — typically one **personal** and one or more **business** profiles. Each profile has its own balances, IBANs, and webhook subscriptions. You must pick **exactly one** profile per GetBlitz connection. To receive payments across multiple profiles, create a separate connection for each.

1. Click **Load profiles**. GetBlitz calls `GET /v2/profiles` with your token — nothing is sent to Wise until you click this button.
2. Wait for the profile list to load (a spinner appears while GetBlitz queries Wise).
3. Click the profile you want to receive payments into.
4. Click **Continue with this profile**.

The selected `profileId` is then merged into the provider config and the rest of the form (connection name) appears.

## Step 4: Save the Connection

1. Give the connection a memorable name (e.g. "Wise EUR — Acme GmbH").
2. Click **Connect**.

GetBlitz will:

- Encrypt and persist the API token + profile ID as connection credentials.
- Call `GET /v4/profiles/{profileId}/balances?types=STANDARD` to list available balance accounts (one per currency).
- Register a webhook subscription via `POST /v1/webhook-subscriptions` for the `balances#credit` event, scoped to your profile.

## Step 5: Select Bank Accounts

Each Wise balance with bank details (IBAN + BIC) becomes a selectable account. Pick the balance(s) you want GetBlitz to use as a payout destination at checkout. EUR balances with a SEPA-reachable IBAN are typical for SEPA Instant flows.

## Webhooks

GetBlitz subscribes to **`balances#credit`** events on the selected profile. When a customer pays, Wise calls the GetBlitz webhook URL with a JSON payload describing the credit.

### Signature Verification

Wise signs every webhook payload with **RSA-SHA256** using their platform-wide private key. GetBlitz verifies the `X-Wise-Signature` header against Wise's public key, which is fetched once from `GET /v1/subscription-types/webhook/public-key` and cached in memory for the lifetime of the process.

This is different from Qonto/Revolut, which use HMAC-SHA256 with a per-merchant shared secret. For Wise:

- There is **no per-merchant webhook secret** to store.
- The verification key is the same for everyone and is rotated by Wise out-of-band — clearing the in-memory cache (or restarting GetBlitz) will pick up a new key.

### Reference Matching

GetBlitz attaches a reference of the form `GB-XXXXXXXX` to every payment QR code. The webhook handler extracts this reference from:

1. The webhook payload's `data.reference` field, if present.
2. The webhook payload's `data.occurrence_id` field, as a fallback.
3. The Wise activities API (`GET /v4/profiles/{profileId}/activities`) — last 20 activities are scanned for an amount + currency match, and the reference is pulled from the activity title/description.

If no reference matches, the webhook is ignored (status `Ignore`) rather than treated as an error — Wise also delivers credits unrelated to GetBlitz (e.g. internal transfers between balances), and we don't want noise in the error logs.

## Sandbox Simulation

When **Sandbox Mode** is enabled, you can trigger a fake incoming credit via the Wise Sandbox topup endpoint without actually moving money. GetBlitz exposes this through the standard "Simulate payment" button on a sandbox connection's detail page.

Under the hood it calls:

```
POST https://api.wise-sandbox.com/v1/simulation/balance/topup
{
  "profileId": <selected profile>,
  "balanceId": <selected balance>,
  "currency":  "EUR",
  "amount":    25.00,
  "details":   { "reference": "GB-XXXXXXXX" }
}
```

Within a few seconds Wise will deliver a `balances#credit` webhook back to GetBlitz, which will then resolve the matching invoice/payment.

## API Endpoints

| Environment | Base URL                       |
| ----------- | ------------------------------ |
| Sandbox     | `https://api.wise-sandbox.com` |
| Production  | `https://api.wise.com`         |

| Endpoint                                               | Used for                       |
| ------------------------------------------------------ | ------------------------------ |
| `GET /v2/profiles`                                     | Profile selector step          |
| `GET /v4/profiles/{profileId}/balances?types=STANDARD` | Listing receivable accounts    |
| `POST /v1/webhook-subscriptions`                       | Registering the credit webhook |
| `GET /v1/subscription-types/webhook/public-key`        | Webhook signature verification |
| `GET /v4/profiles/{profileId}/activities`              | Reference fallback lookup      |
| `POST /v1/simulation/balance/topup` _(sandbox only)_   | Manual payment simulation      |

## Troubleshooting

### "Could not load profiles" on the selector step

- The API token is wrong, revoked, or generated in the wrong environment (sandbox vs production).
- Open Wise → **Settings → API tokens** and confirm the token still exists and is **Full access**.
- If you're in sandbox mode, double-check the token came from `sandbox.transferwise.tech` and not `wise.com`.

### "Failed to list Wise balances"

The token works for `/v2/profiles` but not for `/v4/profiles/{id}/balances`. Possible causes:

- The selected profile no longer exists or you've lost access to it.
- The token is **Read-only** instead of **Full access**. Webhook creation also requires Full access.

### Webhook signature verification fails

- The most common cause is **body mutation by a proxy** (e.g. an HTTP middleware re-serializing the JSON). The signature is computed over the **exact raw bytes** Wise sent — even reordering keys breaks it.
- If Wise has rotated their public signing key, restart the GetBlitz process to clear the in-memory key cache. The cache is per-process and is repopulated on the next webhook.

### Reference is not detected on real payments

- Confirm the customer used the GetBlitz QR code (which embeds the `GB-XXXXXXXX` reference in the SEPA payment text). Manual transfers without a reference will fall back to amount+currency matching against the last 20 activities — collisions or older payments will be missed.

### Sandbox topup returns 200 but no webhook arrives

- Wise sandbox webhooks can lag by 30–60 seconds.
- Verify the webhook URL registered in `POST /v1/webhook-subscriptions` is publicly reachable. Sandbox webhooks won't reach `localhost`; use a tunnel (e.g. ngrok, Cloudflare Tunnel).

## Limitations

- **Single profile per connection.** To accept payments into multiple Wise profiles, create one GetBlitz connection per profile.
- **Single-tenant only.** Personal API tokens belong to the account that generated them. Cannot be used to onboard third-party Wise users — that requires Wise Platform OAuth 2.0, which GetBlitz does not currently support.
- **No automatic key rotation handling.** If Wise rotates their webhook signing key, you must restart the GetBlitz process to refresh the cached public key.
